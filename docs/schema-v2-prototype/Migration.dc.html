UPGRADE STEP · RUNS ONCE PER FIELD

From four text lists to one column schema

Today the column name is also the key under which every value is stored, so renaming a column orphans its data. v2 gives each column a stable key and moves every setting next to the column it belongs to.

Renaming now changes only label. Mapped columns become strict dictionaries: existing values outside the list stay stored and show as codes.

What the upgrade does, per field

  1. 1
    Generate keys
    Lowercase, accents and symbols folded to _, made unique within the field.
  2. 2
    Write the schema
    param1 to param4 become one JSON schema in param1; param2 to param4 are cleared.
  3. 3
    Re-key payloads
    Every user_info_data row, in chunks; above 500 users an adhoc task finishes it.
  4. 4
    Rebuild projection
    Per-set rows and PostgreSQL indexes are rebuilt from the new payloads.
  5. 5
    Keep old reports
    Saved Report Builder columns are mapped from index names to key names.

Until a field's payloads are re-keyed, reads accept both shapes (v1 label keys are resolved through the schema), so a half-finished task never hides data.
